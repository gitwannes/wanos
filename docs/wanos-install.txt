# LCD handling
Your DSI display, which connects to the dedicated ribbon cable port, is handled much more cleanly by the Raspberry Pi OS.
All you need is the correct dtoverlay line in your /boot/config.txt file, which loads the built-in driver for the screen at boot time.
before booting, change in /boot/config.txt
	[all]
	#dtoverlay=vc4-kms-v3d (use this for Pi >= 4)
	#dtoverlay=vc4-fkms-v3d (use this for Pi < 4) (fake KMS)
	#dtoverlay=waveshare-43dsi-5pt-touch
	dtparam=audio=off
# check
# https://www.waveshare.com/wiki/4.3inch_DSI_LCD
# DSI bookworm image: https://drive.google.com/file/d/1iSFRS1mg51q21Jspygy9PPorfrt8_n3t/view
DSI power: /sys/class/backlight/10-0045/

** Enable Hardware Interfaces (I²C & GPIO)
Since the LCD screens and SSR controls are wired to this Pi, you must enable the necessary hardware buses.
Open the Raspberry Pi configuration tool:
sudo raspi-config
	Navigate to Interface Options -> I2C and select Yes to enable the ARM I²C interface.
Install I²C and modern GPIO tools:
sudo apt install -y i2c-tools python3-libgpiod
to test I²C Active: Run i2cdetect -y 1. You should see the grid and the address of your connected LCD (e.g., 27 or 26).

** Configure permanent /dev assignation
edit/create /etc/udev/rules.d/99-rfxcom.rules
this content:
	SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", SYMLINK+="rfxcom"
Save, exit, and reload the USB rules
	sudo udevadm trigger --subsystem-match=tty
check with
	ls -l /dev/rfxcom
